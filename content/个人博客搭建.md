#### 使用 ssg 加 github pages 搭建个人博客，教程中 ssg 使用基于 python 的 mkdocs 工具，原始文档类型使用 markdown

## 前置条件
- 熟悉 `markdown` 语法
- 会使用 `uv` 等 python 工具，可查看 [[UV|UV教程]] 
- 了解 `ssg` 技术原理
- 拥有 github 账号，最好熟悉基本的 github 功能
- 有 git 的使用基础，推荐使用 [[Github Desktop]]，vsc 的 `git graph` 插件体验更佳
- Gui 工具只是优化体验，必须配置原生 git 工具，才能使用 `mkdocs` 的自动化 git 功能，配置所需的令牌自行申请

## 注意事项
- 在 markdown 笔记中谨慎使用图片，md 原生语法对图片排版的格式支持非常弱
- Github 仓库上限为 1 GB，若一定需要插入图片，需要自己衡量推送的图片大小，过大的图片量推荐使用图床，而不是直接推送
- 最好拥有一定的 `css` 基础，虽然 mkdocs 的配置项较为简单，但复杂的格式排版仍需要使用 `css` 实现

## 流程
**1. 撰写对应的 `markdown` 文档**
- 此部分由读者自行完成，不做要求

**2. 初始化仓库**
- 使用 github desktop 创建本地仓库，然后连接到 github，例如 `mynotes`
- 转移到创建的本地仓库文件夹，依次执行以下命令，搭建 mkdocs 工具所需的 python 环境
```
// 初始化python项目
uv init

// 下载python解释器
uv venv --python [版本]

// 下载需要的依赖
uv add mkdocs material --dev

//初始化mkdocs项目
uv run mkdocs new .
```
- 将 `site/` 加入 `.gitignore` 文件

**3. 项目开发**

- 将需要展示的笔记放入 doc 文件夹之后，可以直接将其作为根目录进行访问，写在 `nav` 配置项中，这是 ssg 最重要的一步
- 使用 `uv run mkdocs serve` 指令在本地浏览器 8000 端口查看 ssg 结果，可以热渲染，此指令不会产生构建产物，用于开发阶段

**3. 项目构建**
- 确定 ssg 效果之后，将截至目前的修改提交并推送到 github 仓库，然后运行 `uv run mkdocs build` 创建构建产物 `site/`
- 使用 `uv run mkdocs gh-deploy` 指令自动提交产物并开启 github pages 功能，此命令要求必须安装 git，且必须完成 git 配置，否则只能手动完成流程
- 等待几分钟之后，可以使用以下格式来访问静态站点
```
https://[作者名].github.io/[仓库名称]/[笔记名称]
```
